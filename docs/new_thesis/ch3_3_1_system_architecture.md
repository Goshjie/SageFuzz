# 3.3 方法设计

上一节通过三个场景说明了从 P4LTL 时序规范到可执行测试种子过程中面临的三类挑战。本节给出 P4-BISG 的方法设计，依次介绍系统总体架构（3.3.1）、规范语义规约（3.3.2）、程序上下文建模（3.3.3）、多阶段协同生成与确定性校验（3.3.4）以及统一执行时间线（3.3.5）。

## 3.3.1 系统总体架构与模块交互

P4-BISG 采用分层架构设计，整体划分为四个层级：输入层（Input Layer）、程序上下文层（Program Context Layer）、生成与调度层（Generation and Scheduling Layer）以及结果输出层（Output Layer）。图 3-1 展示了系统的总体架构与模块交互关系。

**图 3-1 P4-BISG 系统总体架构与模块交互关系（占位）**

> 图注说明：图中展示四层架构。输入层接收 P4LTL 时序规范与运行配置；程序上下文层以 ProgramContext 为核心，从编译产物、控制流图、拓扑和可选源码中构建统一证据索引；生成与调度层包含规范语义分析、契约审查、序列构造、规则生成和预言机预测等多个功能模块，模块之间通过结构化中间对象传递数据，并由确定性校验门控进行质量保证；结果输出层将通过校验的工件封装为标准化 testcase 文件。虚线箭头表示审查反馈与回退路径。
>
> 绘图风格参考 Confucius Figure 3：采用分区背景色区分四层，圆角矩形表示功能模块，实线箭头表示正向数据流，虚线/红色箭头表示回退与反馈路径，工具查询用细虚线从 ProgramContext 连接到各生成模块。

该架构的核心设计原则是**确定性骨架与受约束生成的分离**。程序上下文层与结果输出层构成系统的确定性骨架：前者通过索引化的编译产物提供可查询的程序约束，后者通过形式化校验谓词对输出进行质量保证。生成与调度层则负责在确定性约束的引导下，将 P4LTL 时序规范逐步转化为结构化测试工件。这种分离使得生成过程中的错误可以被定位到具体阶段，也使得系统的正确性不依赖于生成模型的一次性准确输出。

生成与调度层内部采用**阶段化的流水线架构**，每个阶段具有明确的输入输出类型和校验条件。阶段之间通过结构化中间对象（而非自由文本）传递数据，从而使错误传播可控。具体而言，系统的工作流按以下阶段顺序执行：

1. **阶段零：上下文初始化。** ProgramContext 构建器加载编译产物、控制流图、拓扑文件和可选源码，建立统一的证据索引。
2. **阶段一：规范语义规约。** 语义分析模块接收 P4LTL 时序规范，结合程序上下文，对时序算子、原子命题和控制面约束进行结构化分解，输出任务规约对象 TaskSpec。
3. **阶段二：TaskSpec 审查与修正。** 审查模块检查 TaskSpec 的语义完整性，如场景是否覆盖正反例、角色是否已绑定到真实主机、观测需求是否可满足。审查失败则触发修正。
4. **阶段三：数据面报文序列构造。** 序列构造模块根据 TaskSpec 中的场景契约，为每个场景生成具有时序依赖的报文序列。生成后由报文审查模块进行协议栈、位宽和角色绑定的确定性校验。
5. **阶段四：控制面规则生成（条件执行）。** 当生成模式要求联合生成控制面规则时，规则生成模块根据表项签名和拓扑信息输出控制面配置。规则审查模块检查合法性。
6. **阶段五：预言机预测。** 预言机模块根据场景结构与程序语义，为每个场景生成预期行为描述，包括到达/丢弃预期、接收主机和状态变化解释。
7. **阶段六：输出封装。** 将所有工件组装为统一的 testcase 结构，生成执行时间线，并落盘为标准化文件。

上述工作流中，阶段一至阶段五的每个生成步骤都可以通过工具查询接口访问 ProgramContext，获取生成所需的程序约束证据。这种"按需查询"的设计避免了将大段编译产物文本一次性注入生成模型的窗口，也使得每个生成决策都可以追溯到具体的程序证据。
