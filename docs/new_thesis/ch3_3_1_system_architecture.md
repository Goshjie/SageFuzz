# 3.3 方法设计

上一节通过三个场景说明了现有方法的局限性以及本章方法需要解决的三个技术难点。本节给出 P4-BISG 的方法设计，依次介绍系统总体架构（3.3.1）、规范语义规约（3.3.2）、程序上下文建模（3.3.3）、多阶段协同生成与确定性校验（3.3.4）以及统一执行时间线（3.3.5）。

## 3.3.1 系统总体架构与模块交互

P4-BISG 采用分层架构设计，整体划分为四个层级：输入层（Input Layer）、程序上下文层（Program Context Layer）、生成与调度层（Generation and Scheduling Layer）以及结果输出层（Output Layer）。图 3-1 展示了系统的总体架构与模块交互关系。

**图 3-1 P4-BISG 系统总体架构与模块交互关系**

该架构的核心设计原则是**确定性骨架与受约束生成的分离**。程序上下文层与结果输出层构成系统的确定性骨架：前者通过索引化的编译产物提供可查询的程序约束，后者通过形式化校验谓词对输出进行质量保证。生成与调度层则负责在确定性约束的引导下，将 P4LTL 时序规范逐步转化为结构化测试用例。这种分离使得生成过程中的错误可以被定位到具体模块，也使得系统的正确性不依赖于生成模型的一次性准确输出。

生成与调度层内部由五个功能模块组成，模块之间通过结构化中间对象（而非自由文本）传递数据。**规范语义分析模块**接收 P4LTL 时序规范，结合 ProgramContext 提供的程序约束，对时序算子、原子命题和控制面约束进行结构化分解，输出任务规约对象 TaskSpec。TaskSpec 随后进入**契约审查模块**，该模块检查其语义完整性（包括场景是否覆盖正反例、角色是否已绑定到真实主机、观测需求是否可满足），审查未通过时将修正反馈返回给规范语义分析模块进行迭代修正。

审查通过的 TaskSpec 作为输入传递给**报文序列构造模块**，该模块根据场景契约为每个场景生成具有时序依赖的报文序列，并经确定性校验检查协议栈、位宽和角色绑定的正确性。在需要联合生成控制面配置的场景中，**控制面规则生成模块**根据 ProgramContext 提供的流表签名和拓扑信息输出控制面规则，同样经确定性校验检查其合法性。**预言机预测模块**根据场景结构与程序语义为每个场景生成预期行为描述，包括到达或丢弃预期、接收主机和状态变化。最终，所有模块的输出被组装为统一的 Testcase 结构并保存为标准化文件。

上述各生成模块均可通过工具查询接口按需访问 ProgramContext，获取生成所需的程序约束证据。这种按需查询的设计避免了将大段编译产物文本一次性注入生成模型的上下文窗口，也使得每个生成决策都可以追溯到具体的程序证据。下面依次详细说明各核心模块的设计。
